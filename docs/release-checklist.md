# 릴리즈 전 브라우저 체크리스트

pytest는 서버와 PTY를 실제로 왕복하지만 프론트엔드를 렌더링하지 않는다. 브라우저
자동화 의존성과 브라우저 바이너리를 기본 개발 환경에 추가하지 않는 대신, UI가 바뀐
릴리즈는 아래 항목을 실제 브라우저에서 확인한다.

## 준비

1. 변경된 서버를 재시작하고 브라우저에서 새로고침한다. 정적 자원 응답이
   `Cache-Control: no-cache`인지도 개발자 도구에서 확인한다.
2. 실행 중인 세션과 종료된 세션이 섞이도록 Claude·Codex·셸 중 둘 이상을 연다.
3. 데스크톱 폭(최소 1200px)과 모바일 폭(390×844 권장)을 각각 준비한다. 모바일
   레이아웃은 개발자 도구의 터치 에뮬레이션으로도 확인할 수 있지만, 소프트 키보드와
   safe area는 실제 폰에서 한 번 더 본다.

## 공통

- [ ] 시스템·라이트·다크 테마에서 사이드바, 탭, 상태줄, 키 바가 모두 읽힌다.
- [ ] 라이브 세션이 일부 행에만 있어도 프로젝트 카드 버튼의 오른쪽 끝이 맞고
      `이어하기`·`새 세션`·`종료`가 줄바꿈되지 않는다.
- [ ] 세션을 시작하거나 종료하면 새로고침 없이 사이드바의 라이브 배지와 버튼이
      즉시 바뀐다. 서버를 재시작해도 상태 채널이 자동으로 다시 연결된다.
- [ ] 터미널 화면과 여백을 누르면 키보드 포커스가 터미널로 오고 입력된다.
- [ ] 탭을 바꾸거나 닫아도 다른 탭의 PTY가 2열로 줄지 않는다.
- [ ] 검색 버튼과 Ctrl+F(macOS는 ⌘F)로 현재 탭의 스크롤백을 찾는다. 입력 중
      일치 항목 수가 바뀌고 Enter·Shift+Enter·이전/다음·Esc가 동작하며, 검색 상자를
      열고 닫아도 PTY 행·열 수가 바뀌지 않는다.
- [ ] Windows/Linux의 Ctrl+C/V와 macOS의 Command+C/V가 동작한다. 선택 없는
      Ctrl+C는 복사가 아니라 인터럽트다.

## 모바일·터치 화면

- [ ] 첫 화면의 프로젝트 서랍은 본문 위에 놓이고 뒤쪽은 어두워진다. 본문을 밀어내거나
      페이지 전체에 가로 스크롤을 만들지 않는다.
- [ ] 세션을 열거나 `보기`를 누르면 서랍이 자동으로 닫히고 터미널이 화면 전체 폭을 쓴다.
- [ ] 서랍 핸들로 다시 열 수 있고, 어두운 뒤쪽을 누르면 닫힌다.
- [ ] 세로·가로 회전과 주소창 높이 변화 뒤에도 탭 줄, 터미널, 키 바가 화면 안에 남는다.
      노치와 홈 인디케이터가 조작부를 덮지 않는다.
- [ ] 기본 터미널 글자는 16px이다. `A−`·`A+`가 12~20px 안에서 모든 열린 탭에
      적용되고, 열·행 수가 다시 맞으며, 새로고침 뒤에도 사용자가 고른 값이 유지된다.
- [ ] 탭 줄의 `검색` 버튼으로 검색 상자를 열고 닫을 수 있으며 소프트 키보드로
      검색어를 입력해도 마지막 터미널 행과 키 바가 화면 안에 남는다.
- [ ] Esc·Tab·Ctrl·방향키·Ctrl-C 버튼이 한 줄 가로 스크롤로 보이고, 버튼을 눌러도
      소프트 키보드가 접히지 않는다.
- [ ] 소프트 키보드를 열어 입력하고 닫은 뒤에도 마지막 터미널 행과 키 바가 보인다.

## 데스크톱

- [ ] 사이드바는 기존처럼 본문 왼쪽에서 폭을 차지하고 접기 상태가 저장된다.
- [ ] 900px 이상에서 좌우 분할·스플리터·탭 이동이 동작하고 두 터미널이 각각 다시 맞는다.
- [ ] 분할된 두 창에서 서로 다른 검색어와 선택 결과를 동시에 유지한다.
- [ ] 물리 포인터 환경에서는 모바일 키 바가 보이지 않는다.

## 명령 검증

```bash
.venv/bin/python -m pytest
.venv/bin/python -m py_compile server/*.py
for file in static/app.js static/modules/*.js; do node --check "$file"; done
git diff --check
```
